# ADR-002: 影子工作区与 Git 级回溯机制 (Shadow Workspace & Git-like Traceability)

## 状态
提议中 (Proposed)

## 背景
为了确保 Agent 在演进过程中的操作安全可控，并满足用户对文件操作“可回溯、可视化”的需求，我们需要一个能够常态化运行的影子工作区。该工作区不仅要隔离 IO，还要能记录每一次文件的增删改减，类似于 Git 的版本控制。

## 决策
1. **常态化拦截**：所有涉及文件系统（Filesystem）的工具调用，默认重定向到影子路径。
2. **操作快照 (Snapshots)**：利用文件系统的轻量级副本或 Git 仓库，在每次写操作前后记录状态。
3. **回溯可视化**：提供 `trace_file_operations` 工具，将操作序列转化为树状图（Tree Graph），清晰展示：
   - 哪个步骤修改了哪个文件。
   - 修改前后的差异（Diff）。
   - 撤销（Rollback）特定操作的能力。
4. **自愈集成**：结晶器在验证新技能时，如果影子环境的操作树不符合预期，则触发自愈逻辑。

## 后果
- **正面**：极大地提高了系统安全性；用户可以直观地看到 Agent 对本地文件的每一个动作；提供了强大的调试和自修复基础。
- **负面**：常态化影子操作会带来一定的磁盘 IO 开销和存储成本；架构复杂度增加。
